What it is

PRE-GEN is an open protocol. Before an AI system generates a real person, brand or work, it asks a registry. The registry answers with a signed decision that anyone can check later.

Read the protocolIntegrateRegistries

How it works

  1. 1. DetectThe provider matches the prompt against the registry's public subject index.
  2. 2. AskPOST /v1/verify/ with the subject and the intended use. The registry returns a signed decision.
  3. 3. ReportAfter generating, the provider files a receipt that ties the output to that decision.

Four answers

dispositionMeaningProvider
allowA licence covers this use.Generate, apply the obligations, file a receipt.
not_blockedPersonal use that nothing prohibits. No licence is granted.May generate under its own policy. Report it; there is no receipt.
reviewThe rights holder has to decide.Do not generate yet.
denyRefused. The PG_* reason code says why and whether retrying can help.Do not generate.

Every decision is canonical JSON signed with Ed25519 and written to a hash-chained audit log. See the protocol overview.

What it does not do

  • It does not stop generation by systems that never ask.
  • A decision proves what the registry answered to a declared request. It does not prove the output matched the request, or that a use is lawful.
  • It is not provenance. C2PA says what was made; PRE-GEN says whether it was allowed. They work together — see C2PA.

One protocol, many registries

The specification and test vectors are Apache-2.0: anyone can run a registry or integrate without asking permission. Each registry gets a four-letter prefix, so codes from different registries never collide (PG-NWRD-000042=). Registries lists who runs PRE-GEN today.

Look up any PG code: pregen.org/lookup.
