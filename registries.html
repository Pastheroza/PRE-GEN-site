Getting listed

Registries open an issue in the specification repository and receive a four-letter prefix (PG codes §8). Bring:

  1. a public API with /v1/verify/, /v1/subjects/index and a rotation-aware key set at /keys;
  2. a passing run of the published test vectors;
  3. a contact for rights holders and a contact for security reports.

Providers are listed by the registry they integrate with, after a production decision and matching receipt.

Working together

Specified: every code belongs to exactly one registry. Bare PG-… codes are the origin registry's; every other registry prefixes its codes with its four letters, so codes never collide. A registry asked about another registry's code points to this list.

Proposed, not yet part of the specification. Discussed in the open before anything changes on the wire.

  • Discovery. Each registry publishes the same machine-readable description of its endpoints and keys, so one provider integration can reach every listed registry.
  • A no is shared. An opt-out or a protection for a minor at one registry should be honoured by every registry holding the same person.
  • Disputes. When two registries claim the same person or work, neither issues new licences for it until the claim is resolved.
